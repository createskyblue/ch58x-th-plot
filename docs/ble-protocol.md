# TH-Plot BLE 协议 v1

实现检查点：2026-10-03（nonce 来源已改为随机源，见下文「每帧 nonce」）。公开固件默认使用 UID 测试派生器，历史请求可在 UID/派生器可用时导出；私有构建可优先接管派生。keygen 页面独立于主上位机，真实商业 FlashID/KDF/激活码规则仍需私有配置。

## 通道与封装

- 名称 TH-Plot，服务 FFE0；FFE1 为 Write（需 ATT 响应），FFE4 为 Notify（须先启用 CCC）。不提供 FFE3 或设备解密接口。
- BOOT 长按切换蓝牙开关：开启为 60 秒广播窗口，连接期间不睡眠；自然断开重新广播，主动关闭则断连且不重开窗口。
- TinyFrame 的一个帧为 `01 | ID[2] | LEN[2] | TYPE[1] | HEADER_CRC[2] | PAYLOAD[LEN] | BODY_CRC[2]`。ID/LEN/CRC 为大端；LEN=0 不发送 BODY_CRC，空帧为 8 字节，非空为 LEN+10。
- HEADER_CRC 覆盖 SOF、ID、LEN、TYPE 共 6 字节；BODY_CRC 只覆盖业务载荷。CRC16 初值 0、反射多项式 0xA001、无末尾 XOR，上游 TinyFrame 实际配置见 APP/include/TF_Config.h。
- 上位机发起的 ID 高位为 1，低 15 位递增。响应沿用请求 ID；历史所有自动帧沿用初始导出 ID。取消/完成使用新的指令 ID，载荷指定目标导出 ID（小端）。CRC/ID 不提供认证或防重放。
- 应用请求最大 128 字节，RX ring 256 字节，TX frame 256 字节；ATT 可分片，不能把一个通知当作完整帧。浏览器上行保守按 20 字节拆包；设备下行按协商 MTU-3 拆包，最大 MTU247。拥塞暂存重试，不重新加密已生成帧；满 RX 返回 ATT insufficient resources。
- 一个普通响应槽加一个异步即时结果槽，客户端普通请求应串行进行；历史期间可以读系统/寄存数据和即时值，但写用户数据或再开历史返回 BUSY。

## 指令

除表中列明外，请求载荷必须为空。未知/非法格式返回 FF。历史导出不接受 offset/count、范围或分页参数；历史导入的计数和顺序偏移见下文。

| 请求 TYPE | 操作 | 请求载荷 | 成功响应 TYPE / 载荷 |
|---|---|---|---|
| 01 | SYSTEM_INFO | 空 | 81 / 52 字节系统信息 |
| 02 | USER_READ | 空 | 82 / 长度 u8 + 原样字节 |
| 03 | USER_WRITE | 0～64 字节 | 83 / status u8=0 |
| 04 | READ_LATEST | 空 | 84 / 9 字节测量结果 |
| 05 | SYSTEM_REBOOT | 空 | 85 / status u8=0（随后软件复位） |
| 06 | ACTIVATION_VERIFY | 空 | 86 / valid u8（0未激活，1校验通过） |
| 07 | SETTINGS_READ | 空 | 87 / history_mode u8 + refresh_on_change u8 |
| 08 | SETTINGS_WRITE | history_mode u8 + refresh_on_change u8 | 88 / status u8=0 |
| 09 | WINDOW_READ | 空 | 89 / window_index u8 |
| 0A | WINDOW_WRITE | window_index u8 | 8A / status u8=0 |
| 10 | HISTORY_ALL | 空 | 90 BEGIN → 91 DATA（多帧）→ 92 END |
| 11 | HISTORY_CANCEL | 目标导出 ID u16 LE | 93 / status u8=0 |
| 12 | HISTORY_COMPLETE | 目标导出 ID u16 LE | 94 / status u8=0 |
| 20 | IMPORT_BEGIN | version u8 + mode u8 + history_count u16 LE + recent_count u16 LE | A0 / status u8=0 |
| 21 | IMPORT_DATA | sample_offset u16 LE + 1～30 个温湿度点 | A1 / next_sample_offset u16 LE |
| 22 | IMPORT_COMMIT | 全部样本字节的 CRC32 u32 LE | A2 / status u8=0 |
| 23 | IMPORT_CANCEL | 空 | A3 / status u8=0 |

错误响应 FF：`status u8 | request_type u8`，status 为 INVALID=1、BUSY=2、UNAVAILABLE=3、IO_ERROR=4、TIMEOUT=5、NOT_ACTIVATED=6。取消目标不存在/ID不符、提前完成 ACK 都为 INVALID。通知底层致命失败无法保证再发错误帧，立即解冻并等断连/重新启用通知建立新传输状态。

### 激活与设备设置

06 用本机 UID 与设备内存储的激活码重新校验，返回布尔值；不会因为 CSV 测试模式自动授权。网页上位机在连接后及写入激活码后查询，通过且成功读取设置才启用设备设置控件。设置读取失败单独提示并禁用设置控件，保留蓝牙连接、即时测量及历史导出。07/08 每次请求都独立重新校验，不依赖客户端先发过 06，也不缓存连接时的权限。微信小程序已废弃，后续仅维护网页上位机。

设置为两个字节：history_mode=0 表示长期 30 天 5 分钟模式（最近一天仍保留分钟点），1 表示完整 7 天分钟模式；refresh_on_change=0 默认关闭，1 开启变化刷新。其他值和长度返回 INVALID。08 在历史导出或刷屏作业中返回 BUSY，未激活返回 NOT_ACTIVATED。切换模式会清空设备历史，并保留当前最后读数作为新起点，上位机须提示；开启变化刷新须提示续航降低及空调周期变化引起频繁刷屏。

设置存于 Data Flash 0x4000/0x5000 的独立 A/B 副本，与 0x2000/0x3000 的激活码分开，重启后保留。写入后回读确认已提交值再应用运行设置；一份有效新副本已提交时，即使另一份修复失败也采用回读的新值。重复相同设置不会擦写。变化刷新包含曲线；成功图表刷新会重新开始自动刷新计时，失败及控制器图像回送不重置，蓝牙/电量的顶栏刷新也不推迟图表计时。

设置区可重置：启动时若两份记录均无效、格式或设置值无效，会丢弃这些记录并写入默认值（30 天模式、变化刷新关闭），不解析或迁移旧 epoch 数据。空白设置区直接采用默认值，不擦写；有效设置照常保留。读操作失败时禁止默认值重置；重置写入失败且无有效副本时仍报存储错误。激活码区保持原有校验规则，不随设置重置。

### 屏幕时间范围

09/0A 每条请求都独立校验设备激活状态，未激活返回 NOT_ACTIVATED。09 读取 `AppDisplay` 当前选中的范围索引，0A 直接选择该索引。它们不依赖 07/08 的记录设置，不写 Flash，不改变记录模式或历史数据；重启按原有开机逻辑选择范围（正常构建已激活默认 1 天，未激活默认 1 小时，CSV 启动预填构建为 7 天）。

| window_index | 范围 |
|---|---|
| 0 | 1 小时 |
| 1 | 2 小时 |
| 2 | 3 小时 |
| 3 | 4 小时 |
| 4 | 6 小时 |
| 5 | 8 小时 |
| 6 | 12 小时 |
| 7 | 1 天 |
| 8 | 7 天 |
| 9 | 30 天 |

09 请求载荷必须为空；0A 必须恰好一个字节，索引越界返回 INVALID。导入期间或已接受重启时，0A 返回 BUSY；09 仍可读取。显示作业进行中允许选择，沿用按键切窗的待刷新队列：当前作业完成后绘制最新范围，连续选择合并为一次后续刷新。重复选择同一档不追加刷新。8A 表示选择已接受，随后 89 返回当前选中值，不代表物理屏幕已完成刷新。

网页「设备设置 → 屏幕时间范围」在连接并激活后自动读取，也可点「读取当前」同步设备按键产生的变化。选好范围点「切换范围」，应答后再次读取设备状态。范围读取失败只禁用范围选择，保留蓝牙及其他控件；再次读取成功即可恢复。网页导入或导出期间暂停范围操作。

### 系统信息 81（32 或 52 字节）

前 32 字节是 v1 格式，所有固件都发；后面的 20 字节编译时间戳只有新固件才带。上位机靠长度区分两者，不能拿 `info[0]` 判断：那样会让旧上位机把新固件当成「不是 TH-Plot」。

| offset | 字段 |
|---|---|
| 0 | 协议版本 u8=1 |
| 1 | 硬件 UID 可用标志 u8 |
| 2 | 用户存储可用标志 u8 |
| 3 | 传感器 u8：0未发现、1 AHT20、2 SHT40 |
| 4 | 芯片 UID 原始 8 字节，来自 SDK CMD_GET_UNIQUE_ID，不是 MAC |
| 12 | SDK chip_info u32 LE，**不是 FlashID** |
| 16 | history capacity u32 LE=8640（5 分钟粒度 × 30 天） |
| 20 | recent capacity u32 LE=1440（1 分钟粒度 × 1 天） |
| 24 | 设备运行毫秒 u32 LE（会回绕，不是 Unix 时间） |
| 28 | 用户寄存上限 u8=64 |
| 29 | FlashID 可用标志 u8=0，尚未确定读取方式 |
| 30 | 派生模式 u8：0不可用、1私有、2公开 UID 测试 |
| 31 | flags u8，bit0=当前构建启动预填模拟历史，其余为0 |
| 32 | 固件编译时间 ASCII 20 字节，`__DATE__ " " __TIME__` 原样发，形如 `"Mmm dd yyyy hh:mm:ss"`（日号空格补齐，恒 11+1+8 字节） |

编译时间取的是 `APP/AppCommunication.c` 最后一次编译的时间，不是链接时间；增量编译下可能早于整个镜像的构建时间，要拿到准确时间就完整重建。旧固件只发 32 字节，上位机显示「固件未上报」，不当作错误。

网页上位机将时间显示为 `yyyy-MM-dd hh:mm:ss`，例如 `2026-10-07 08:38:34`；只转换显示格式，不改变协议数据，也不做时区换算。

### 系统重启 85

请求载荷必须为空，历史导出进行中返回 BUSY（否则客户端正在收的半份历史会被直接掐掉），构建没有复位实现时返回 UNAVAILABLE。设备先把 85/status=0 排进通知发送队列，等 `PROTOCOL_REBOOT_DELAY_MS`（200 ms，见 `APP/include/AppProtocol.h`）到点再调 `SYS_ResetExecute()`，让 ACK 有空口时间发出去。

复位是整颗芯片的软件复位，和上电走同一条启动路径：BLE 窗口状态在 RAM 里，复位后不再广播，**必须长按 BOOT 重新开窗口**才能再连。上位机和网页端都在发指令前弹窗说明这一点。延时若跨过断连也会照常复位，指令不依赖链路存活。

### 即时测量 84（9 字节）

`status u8 | temperature_tenths i16 LE | humidity_tenths i16 LE | measured_uptime_ms u32 LE`。status=0 为有效，4 为传感器失败（值置零）；请求超时为 FF/TIMEOUT。

真正调用非阻塞传感器状态机，最多 2 秒，不额外写历史/采电池/改周期。与已有周期转换重合时可以返回请求后完成的测量，不返回上次缓存。断连/关闭通知/超时/发送故障统一取消协议与 APP 的待响应所有权；仅由该按需请求启动的转换退出状态机，周期转换不中断，新请求不沿用被放弃请求的状态。

### 用户寄存

0～64 字节任意原始值，0 字节写入表示清空。无验码、自动 trim、截断或加解密；READ 总是返回长度加值。Flash 写后回读验证；相同内容不重复擦写。超长返回 INVALID，历史冻结期间写返回 BUSY。用户寄存值绝不是设备侧加密 key 来源。

## 全量历史流程

历史数据由 `APP/AppHistory.c` 独占管理。采样通过 `AppHistory_Record` 追加；绘图只借用裁剪后的只读分段；导出通过独占读锁和按序读取 API 获取数据。存储模块不依赖显示、蓝牙或硬件，自动刷新策略独立放在 `DisplayRefreshPolicy`。

两个模式复用同一静态缓冲区：最近区 1440 点、较早区 8640 点，每点温湿度共 4 字节，样本占 40320 字节，RV32 历史结构共 40332 字节。模式切换清空计数并保留最后一点，不对旧数据做迁移或插值。导入直接复用此缓冲区，不分配第二份历史。

1. HISTORY_ALL 现场派生本次导出的密钥（UID+盐），私有派生器/UID 不可用则直接拒绝且不冻结、不降级明文。不分配持久序号，也不写任何 Flash。
2. 冻结全设备唯一历史对象的所有写入口，锁定两个有效计数。
3. 自动推送 BEGIN，随后 DATA 直到所有有效记录完成，再 END。
4. 客户端检查完整性并发 HISTORY_COMPLETE，设备仅在正确目标、已产生 END 且本地发送帧排空时接受；此时解冻，再发 94。客户端收到 94 后进度才显示 100%。这不等于客户端解密或认证通过。
5. 取消、断连、关闭通知、发送/加密故障、连续 3 秒没有成功收/发一帧会解冻（每成功一帧重置计时，不设整体时长上限）。等待客户端 ACK 同样受期限保护。失败客户端丢弃全部本次结果，从头请求；无续传。

冻结只禁止历史追加、每小时归档、淘汰和 reset；周期测量/顶栏继续，图表不因被冻结的新采样反复重画，按键仍可手动刷新/切窗。到期历史样本跳过而非排队回补，冻结跨采样边界会形成未记录时段；现有历史无每点时间戳及 skip_count，禁止据名义密度伪造精确墙钟采样时间。

### BEGIN 90（24 字节）

| offset | 字段 |
|---|---|
| 0 | version u8=1 |
| 1 | flags u8：bit0=长期压缩段，bit1=模拟历史预填构建（值1或3） |
| 2 | history_count u16 LE |
| 4 | recent_count u16 LE |
| 6 | reserved u16=0 |
| 8 | history_step_seconds u32 LE=300（名义粒度） |
| 12 | recent_step_seconds u32 LE=60 |
| 16 | effective_seconds u32 LE（有效记录跨度，不是绝对时间） |
| 20 | total_plaintext_bytes u32 LE=(history_count+recent_count)*4 |

调试加速构建的名义步长遵循 TrendHistory 定义。长期 8640 点（5 分钟粒度，约 30 天）、最近 1440 点（1 分钟粒度，约 1 天），最大 10080 点 / 40320 字节。最近区是滑动窗口：存满一天后每 5 分钟把最旧的一个 5 分钟槽按 LTTB 面积判据压成长期区的 1 个点，所以 1 分钟粒度始终覆盖最近一天，不会整小时、更不会整天一次性降精度。LTTB 不是每 5 分钟的精确平均或均匀实测时间戳。

### DATA 91（16～208 字节）

`offset u32 LE | nonce[12] 明文 | ciphertext[N]`，N 为 4 的倍数且不超过192。offset 为本次数据流输出偏移，不是客户端查询参数。

明文顺序：长期数组有效区从旧到新，然后最近数组有效区从旧到新；每个记录为 `temperature_tenths i16 LE | humidity_tenths i16 LE`。

每 DATA 独立 ChaCha20：32 字节真实设备 key（本次导出开始时由 UID+盐现场派生，不读 Flash），96-bit nonce，block counter 从1开始。**nonce 不持久化、不含序号**：12 字节 = 3 个 32 位随机数，按小端铺开。真机随机源是 SDK 的 `tmos_rand()`，它不是纯 LCG —— 每次调用先把当前时钟加进状态再做一轮 LCG，所以同一台设备不同次导出拿不到同一串 nonce，掉电/擦除也不会把序列重置回起点（旧的「持久 epoch」方案就会）。代价是唯一性来自「时钟一直在走」，不是构造上保证；`HAL/MCU.c` 注册的 `cfg.srandCB` 只影响上电初值。同一已生成的帧因拥塞可重发同一密文，不能用相同 nonce 加密变化的内容。接收器检查连续偏移、总数/字节一致、重复帧完全相同及不同帧 nonce 不重复。

### END 92（8 字节）

`total_plaintext_bytes u32 LE | freeze_elapsed_ms u32 LE`。elapsed 是冻结至生成 END 的耗时，不包括之后等待 ACK 的时间。每帧 TinyFrame CRC 加连续偏移/总数检查提供传输差错检测；没有额外整流 CRC/MAC。客户端进度=(已接收不重复有效字节/total)，不计帧头/nonce/重复帧；空历史同样需要 END 和 ACK。

## 测试历史导入

网页「全部历史 → 导入测试历史」选择历史 CSV 后，先在主图和缩略图显示本地文件预览，不需要蓝牙连接或激活，也不发送导入指令。绝对日期按 CSV 标题中的 UTC 时区还原；相对时间 CSV 以预览时刻为起点。预览保持所有点和原值，可缩放、拖动、悬停查看；图表注明本地文件来源，导入、取消或断连后仍保留预览。获取设备历史会替换为设备数据。

点「导入设备」才读取当前设备颗粒度并校验 CSV；不匹配的文件可以预览，但不会上传。确认替换后串行发送 20 → 21（多次）→ 22。导入设备须通过激活校验并成功读取设备设置；固件每条导入指令也独立校验激活状态。导入期间禁止历史导出、设置修改、激活码写入及重启，即时测量和只读查询仍可使用。

20 载荷固定 6 字节：`version=1 u8 | mode u8 | history_count u16 LE | recent_count u16 LE`。mode 必须等于当前设备设置，较早区 0～8640 点，最近区 1～1440 点。显示正在刷新、导出占锁或等待重启时返回 BUSY。非法元数据不会清空原历史；成功开始则清空已发布计数并独占存储，未完成的数据不能被绘图或导出读取。

21 载荷为 `sample_offset u16 LE | {temperature_tenths i16 LE, humidity_tenths i16 LE} × N`，N=1～30，载荷 6～122 字节。顺序为较早区从旧到新，然后最近区从旧到新。offset 单位是点，第一块必须为 0，随后必须等于上次 A1 返回的 next_sample_offset。重复、乱序、越界块返回 INVALID；整块校验通过才写入。温度范围 -400～1250，湿度 0～1000，均为十分之一单位。

22 的 CRC32 覆盖按导入顺序拼接的全部样本字节，不含 offset、元数据或 TinyFrame 封装；采用反射多项式 0xEDB88320、初值 0xFFFFFFFF、末尾 XOR 0xFFFFFFFF（ASCII `123456789` 为 0xCBF43926）。只有接收总数完整且 CRC 匹配才发布历史，并请求屏幕刷新当前时间窗口。校验失败返回 INVALID，客户端应取消后重新开始。

23 取消当前导入。断连、关闭通知、传输致命错误、激活失效或连续 10 秒没有成功导入请求推进也会取消并解锁。**开始替换后，取消或中断会留下空历史；没有旧数据回滚副本。** 成功导入的数据只存 RAM，重启会丢失并恢复正常采样；导入不改持久设置。

CSV 接受本网页导出的 `时间 (UTC±HH:MM),温度 (°C),湿度 (%)`，以及模块导出的 `seconds_ago,temperature_c,humidity_percent`（可附带 density、contains_simulated_history 列）。行必须从旧到新、值为 0.1 精度，最多 10080 点。7 天模式全部连续间隔 60 秒；30 天模式较早区间隔 300 秒、最近区间隔 60 秒，各区不能超容量。网页在 BEGIN 前校验，不排序、补点或重采样；原始温湿度值逐点保留。固件存相对时间，导入后以最后一点为当前起点，不保留 CSV 的绝对日期。

## Flash 与私有构建

DataFlash 相对地址；4096字节擦除块：用户寄存值 user A2000/B3000，设备设置 A4000/B5000，默认 BLE SNV7000 不共用擦除块。两种记录复用 version u8、length u8、reserved2、raw64 格式，设置的 length=2，FlashStore 另加12字节头。对齐的256字节 scratch 负责 SDK read/write，禁止跨写页，独立4KiB擦除。nonce 不持久化，导出不写 Flash。

用户寄存值：双份全擦空视为未写入，写失败/损坏/回滚都不影响加密（密钥不依赖它）。原来每次导出会把 epoch 计数写进 A/B 并回读确认，那意味着一次导出各擦一次 4096 字节块、没有任何磨损均衡；现在 nonce 不持久化，导出不再写 Flash，这个磨损点消失。代价是 nonce 唯一性从「可证明不重复」变成「依赖随机源里的时钟混合」（见上文「每帧 nonce」）；把同一 key 用于多设备仍会破坏唯一性，生产维护需换 key 或明确新密钥域。

公开测试派生：盐2 UTF-8 `createskyblue@outlook.com`（25字节）右补7个零作为32字节ChaCha20 key；nonce=`ASCII THK1 + SDK原始8字节UID`；counter=1，输入32个零，输出32字节历史key。激活码为输出的64字符小写HEX。用户明确要求的盐2已公开，不提供商业保密。宏集中于 `APP/include/AppConfig.h`：`TH_PLOT_TEST_ACTIVATION=1` 默认公开测试，0且无私有provider则拒绝。私有构建定义 `TH_PLOT_PRIVATE_KEY`，外部 `HistoryPrivate_DeriveKey(uid[8], key[32])` 优先且失败不回退公开盐；生产秘密/FlashID依旧由私有构建负责。

## 上位机与安全限制

`web/index.html` 成功连接后自动原样读寄存值，并自动发一次 READ_LATEST 把当前温湿度显示出来；首次测量失败只提示不断链（链路是好的，不该因为一次采样把连接拆掉）。解码器接受64个ASCII HEX字符表示32字节key。本页不含/不加载盐或派生算法。独立 `tools/keygen/keygen.html` 手工粘贴UID生成及复制激活码，无BLE连接/写入/自动填码；默认盐2公开，调整生成器盐不修改固件。主上位机本地解密并导出CSV/密文JSON，不上传值。

明确没有 Poly1305/MAC/防重放。nonce/CRC/ID/格式与范围检查不能证明真实性，错误 key 可能得到貌似有效的数据；被托管的激活码在开放的 BLE 操作窗口内可读，不能称为DRM。

参考：RFC 8439 第2.3/2.4节的 ChaCha20 与 nonce 规则，Chrome 官方 Web Bluetooth 文档的 secure context/permission/notification 规则。本轮不烧录、不推送、不启用读保护；协议互操作/模拟 Flash/模拟 DOM 测试不代替硬件测试。
